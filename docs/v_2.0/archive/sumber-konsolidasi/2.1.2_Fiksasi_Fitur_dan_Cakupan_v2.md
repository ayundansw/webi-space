# 2.1.2 Fiksasi Fitur dan Cakupan — WEBI-SPACE v2.0

**Status:** Final, sudah melalui satu putaran tinjauan ulang, seluruh gap dari tinjauan sudah ditutup. Hasil kompilasi seluruh keputusan dari 2.1.1 dan tiga dokumen rancangan (Konten Dinamis, Manajemen Proyek, Praktik). Dokumen ini acuan tunggal fitur v2.0, sama fungsinya seperti 1.2 di v1.0.

**Prinsip dasar dokumen ini:** seluruh fitur v1.0 yang TIDAK disebutkan di dokumen ini (autentikasi, RBAC dasar, guardrail evaluasi WEBI, sistem notifikasi terpadu, kontrol akses attachment, dst) TETAP DIPERTAHANKAN apa adanya. Dokumen ini cuma mendaftar yang berubah atau baru, bukan daftar ulang seluruh sistem dari nol.

---

## 1. Fondasi Lintas Portal

1. Shell terpadu: navbar fixed (tidak ikut scroll) + sidebar interaktif (hover, ikon per menu, collapsible di desktop) + area konten, satu implementasi dipakai tiga portal.
2. Responsive presisi di semua ukuran perangkat, dibangun ke shell sejak awal.
3. Breadcrumb dan konsistensi bahasa/fitur di seluruh halaman.
4. Navigasi lintas portal (Eksplorasi ke Eksekusi) untuk user dengan akses ganda.
5. Logo/aset identitas visual WEBI-SPACE.
6. Sapaan dinamis (variasi kalimat) di heading dashboard, satu komponen dipakai tiga portal.
7. Pengurangan beban teks lewat ikon dan warna kontras di tampilan berbasis daftar/teks padat.

## 2. Portal Admin

1. Dashboard redesign, prioritas efisiensi scanning information, menampilkan ringkasan Eksplorasi (progres, leaderboard), Eksekusi (proyek aktif, alert), dan akses cepat Log WEBI (sudah ada dari v1.0, styling disempurnakan).
2. Detail penuh Project Ideas via popup/halaman detail, bukan cuma card statis.

## 3. Portal Eksplorasi

### Fitur Wajib

1. Dashboard redesign, menampilkan leaderboard, progres, level, dan entry point WEBI kontekstual.
2. Profil: CRUD nama/email/password, logout.
3. Avatar: satu avatar terbuka tiap naik satu level, dipilih dari yang sudah terbuka. Mekanisme khusus Eksplorasi ini TIDAK sama dengan Avatar Eksekusi (lihat bagian 4, poin 2). Aset visual disiapkan terpisah oleh Aye, logic unlock oleh Claude Code.
4. WEBI kontekstual: hadir langsung di halaman relevan (dashboard, unit), tidak wajib buka menu chat terpisah untuk bertanya soal materi yang sedang dibuka.
5. WEBI menu chat khusus tetap ada (untuk ngobrol bebas), dengan riwayat percakapan tersimpan, bisa dibuka ulang dan dilanjutkan.
6. Leaderboard ditampilkan ke anggota (pembalikan keputusan v1.0, lihat 2.1.1 bagian 2).
7. Peta Kurikulum: visualisasi ulang bergaya roadmap.sh (diagram hierarki jalur), interaktif dan responsif. Mekanisme lock/unlock tidak berubah dari v1.0.
8. Modul Konten Dinamis: sistem blok konten (Heading H1-H6, Teks, Gambar via link eksternal, Callout, Kode, Video embed, List, Custom HTML), disusun lewat form terstruktur di admin panel, satu renderer generik dipakai semua materi. Seluruh 67 unit lama dimigrasi manual ke sistem ini. **Migrasi ini sekaligus menutup dua utang teknis lama dari CLAUDE.md v1.0: fitur upload file untuk intermezo Modul 6, dan UI evaluasi campuran Unit 5.8 yang belum rapi. Keduanya diselesaikan sebagai bagian dari rewrite total konten, bukan ditambal terpisah. Wajib diverifikasi eksplisit saat 2.2.4 selesai bahwa dua item ini benar tertutup, baru ditandai lunas di CLAUDE.md.**
9. Kuis: flow terpisah dengan CTA setelah materi, tanpa timer dan tanpa lock. Skor TERBAIK dari seluruh percobaan yang dipakai untuk akumulasi poin/leaderboard. Retry tanpa batas. Feedback analisis jawaban vs kunci dipertahankan. Ini menggantikan penuh mekanisme poin Kuis v1.0 (attempt pertama penuh, berikutnya nol). **Data submission Kuis lama dari masa usability testing v1.0 diperlakukan sebagai arsip riwayat saja, TIDAK dihitung ulang pakai logic skor-terbaik yang baru. Logic baru cuma berlaku untuk percobaan yang dibuat setelah mekanisme v2.0 ini aktif.**
10. Modul Praktik: challenge berjenjang (low/mid/high), dipilih bebas tanpa gating dari progres Materi. Tiap challenge punya track map (langkah panduan, dibangun dari sistem blok yang sama seperti Konten Dinamis). Submission berupa link/teks/file, direview oleh PIC atau anggota eksekusi yang di-assign PIC per-submission (RBAC ketat, reviewer cuma akses submission yang ditugaskan ke dia). Submit ulang tanpa batas dengan label versi eksplisit, poin diminishing return (submission pertama penuh, berikutnya lebih kecil). Tidak ada starter code, cukup instruksi konkret di track map.

### Sistem Poin Terpadu

Materi, Kuis, dan Praktik menyumbang ke SATU akumulasi poin dan level yang sama, dipakai bersama untuk leaderboard, progres dashboard, dan personalisasi WEBI. Threshold level dihitung ulang setelah seluruh sumber poin ini terbangun (lihat Roadmap 2.2.7). Sistem poin/level ini KHUSUS Eksplorasi, tidak ada padanannya di Eksekusi.

## 4. Portal Eksekusi

### Fitur Wajib

1. Dashboard redesign, menampilkan ringkasan proyek, Kalender Personal, dan akses Forum General.
2. **Profil dan Avatar, mekanisme terpisah dari Eksplorasi.** Tidak ada sistem poin/level di Eksekusi, jadi tidak ada lock/unlock. Anggota eksekusi bisa langsung memilih bebas dari galeri avatar yang disediakan, tanpa syarat apa pun. Ini keputusan sadar untuk efisiensi, bukan kekurangan desain.
3. Forum General: satu forum umum lintas proyek (info lomba, pengumuman), akses `execution_member` dan `admin` saja.
4. Forum Proyek: satu thread per proyek, muncul sebagai tab di halaman proyek, akses sama seperti Forum General.
5. Halaman utama proyek dengan navigasi tab: Kanban (default), Roadmap, Gantt, Kalender, Forum Proyek, Anggota.
6. Kanban: board utama tetap bersih, cuma menampilkan task besar (bukan subtask).
7. Detail task: panel geser dari samping (slide-over), bukan halaman terpisah.
8. Subtask: task mini dengan assignee dan status sendiri, nested di dalam panel detail task induk, tidak muncul di board Kanban utama.
9. Milestone: dipertahankan dari v1.0, jadi basis data Roadmap.
10. Roadmap: timeline milestone level tinggi.
11. Gantt Chart: bar per task dengan tanggal mulai-selesai, mendukung dependency antar task (blocked-by/blocks). Kalau dependency molor, sistem kasih indikator visual, TIDAK auto-reschedule.
12. Kalender, dua tingkat:
    - Tab Kalender per proyek (filter satu proyek).
    - Kalender Personal (halaman tersendiri, agregat semua proyek yang diikuti user, plus Acara umum lintas proyek).
    - Dua kategori: Kegiatan (`#1C1515`, otomatis dari deadline Task/Milestone) dan Acara (`#05D9E7`, input manual: kompetisi, meeting, kumpulan rutin).
13. Project Ideas: dipertahankan dari v1.0, dengan detail popup (lihat Portal Admin poin 2).

## 5. Batasan Sistem v2.0

Disepakati secara sadar TIDAK dibangun di v2.0:

1. WEBI di Portal Eksekusi. Dicoret sepenuhnya, fokus Eksekusi ke forum dan manajemen proyek.
2. Auto-reschedule cascading di Gantt Chart. Cukup indikator visual saat dependency molor.
3. Kuis real-time serentak gaya Kahoot/Wayground (timer bersama, sesi live). Kuis tetap independen per orang, dikerjakan kapan saja.
4. Starter code/template teknis untuk Praktik. Cukup instruksi konkret di track map.
5. Role RBAC baru "mentor". Delegasi review Praktik memakai flag per-submission (`assigned_reviewer_id`) ke `execution_member` yang sudah ada, bukan role baru.
6. Editor konten gaya Notion (slash-command, rich text bebas). Konten Dinamis memakai form terstruktur (pilih tipe blok dari dropdown), bukan editor bebas ketik.
7. Upload file gambar native ke server untuk materi. Gambar memakai link eksternal (Cloudinary/imgur/dst).
8. Environment staging/branch terpisah untuk pengembangan v2.0. Dikerjakan langsung di production yang sama, sesuai keputusan Aye (v1.0 belum rilis resmi, belum ada data yang dianggap final).
9. Sistem poin/level di Portal Eksekusi. Avatar Eksekusi memakai pilihan bebas tanpa syarat, bukan diturunkan dari mekanisme gamifikasi apa pun.

**Ditunda, bukan dibatalkan:**
- Landing page di `rit-base.online`, dikerjakan paling akhir (2.2.8).
- Dokumen Maintenance (backup, monitoring cron), dikerjakan di Fase 2.3.
- Kriteria keberhasilan v2.0 tahap usability testing anggota, dikerjakan setelah v2.0 live.
